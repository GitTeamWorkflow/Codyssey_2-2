# 🟩 Git 리셋으로 되돌리기 (git reset)  

이미 만든 커밋을 취소하고 이전 시점으로 되돌아가는 `git reset`에 대해 배운다. 특히 실무 및 과제 요구사항에서 자주 사용하는 `--soft HEAD~1` 옵션을 집중적으로 다룬다.  

<br><br>

## 🟢 git reset 이란?  
- 시간을 과거로 되돌리는 명령어다. 지정한 커밋 시점으로 내 저장소의 상태를 완전히 리셋한다.  
- 리셋하는 방식에 따라 크게 3가지 옵션(`--hard`, `--mixed`, `--soft`)이 있다.  

<br><br>

## 🟢 reset의 3가지 옵션 비교  

| 옵션 | 커밋 기록 삭제 여부 | 스테이지 상태 유지 여부 | 작업 폴더 파일 유지 여부 |
| --- | --- | --- | --- |
| `--soft` | 삭제됨 | **유지됨 (Stage 상태)** | **유지됨** |
| `--mixed` | 삭제됨 | 취소됨 (Unstaged 상태) | **유지됨** |
| `--hard` | 삭제됨 | 취소됨 (모두 삭제) | 삭제됨 (모든 변경사항 유실) |

<br><br>

## 🟢 실습: 최근 커밋 취소하고 작업물 살려두기 (--soft HEAD~1)  
- 버전을 방금 커밋했는데, 메시지를 잘못 썼거나 무언가 추가 설정을 빠뜨렸을 때 가장 많이 쓰는 복구 방법이다.  
- `HEAD~1`은 '바로 직전(현재 기준 1개 이전) 커밋'을 가리키는 특수한 표현이다.  

### 🟡 1. 실습용 파일 만들고 커밋하기  
- 파일 하나를 만들고 커밋한다.  
    ```bash
    touch update.txt
    git add update.txt
    git commit -m "feat: add update.txt"
    ```

### 🟡 2. 최근 커밋 취소하기  
- 아래 명령어를 입력하여 방금 만든 커밋을 취소한다.  
    ```bash
    git reset --soft HEAD~1
    ```

### 🟡 3. 취소 상태 확인하기  
- `git status`를 입력하여 상태를 확인한다.  
    ```bash
    git status
    ```
- 커밋은 사라졌지만, 방금 커밋했던 `update.txt` 파일이 **스테이지(Stage)에 초록색 글씨로 고스란히 남아 있는 것**을 볼 수 있다.  
- 이 상태에서 수정한 뒤 다시 정상적으로 커밋을 진행하면 된다.  

<br><br>

## ⚠️ reset 사용 시 주의사항  
- `git reset`은 내 컴퓨터의 히스토리를 강제로 수정하는 명령어다.  
- **이미 원격 저장소(GitHub)에 push 완료한 커밋에 대고 reset을 사용하면 안 된다.**  
- 협업 중인 다른 팀원들의 컴퓨터에 있는 커밋 기록과 꼬이게 되어 엄청난 충돌이 발생한다. 이미 push된 커밋은 아래에서 배울 `revert`를 사용해야 한다.
