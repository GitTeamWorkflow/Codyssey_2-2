# 🟩 방금 만든 커밋 수정하기 (git commit --amend)  

버전을 방금 막 만들었는데 오타가 있거나, 깜빡하고 빼먹은 파일이 있을 때 새 커밋을 구질구질하게 또 만드는 대신 '방금 전 커밋'에 덮어쓰는 마법 같은 방법을 배운다.  

<br><br>

## 🟢 커밋 메시지에 오타가 났을 때  
- 마지막 커밋 메시지를 잘못 적었을 때, 기록을 남기지 않고 즉시 수정할 수 있다.  
    ```bash
    git commit --amend -m "수정할 새로운 커밋 메시지"
    ```
- 이 명령어를 치면 직전에 만들었던 커밋 메시지가 새 메시지로 완전히 교체된다.  

<br><br>

## 🟢 커밋할 때 파일을 깜빡하고 빼먹었을 때  
- 파일 A와 파일 B를 같이 묶어서 버전으로 만들었어야 했는데, 실수로 파일 A만 스테이지에 올리고 커밋해 버렸을 때 사용한다.  

### 🟡 해결 순서  
- 1. 깜빡했던 파일 B를 스테이지에 올린다.  
    ```bash
    git add fileB.txt
    ```
- 2. 메시지는 그대로 둔 채 커밋에 덮어쓴다.  
    ```bash
    git commit --amend --no-edit
    ```
    - `--no-edit` 옵션은 커밋 메시지를 고치지 않고 그대로 유지하겠다는 뜻이다.  
- 결과적으로 두 번째로 올린 파일 B가 첫 번째 커밋 속으로 쏙 들어가서 마치 처음부터 같이 커밋된 것처럼 합쳐진다.  

<br><br>

## ⚠️ 주의사항 (가장 중요)  
- `git commit --amend`는 이미 내 컴퓨터(Local Repository)에만 있고, Github 등 **원격 저장소(Remote Repository)에 올리지 않은(Push 하지 않은) 커밋에만 사용해야 한다.**  
- 이미 Github에 올라간 커밋을 덮어쓰면 다른 사람들과 협업할 때 버전 기록이 꼬여서 큰 충돌이 일어날 수 있다.
