# 🟩 변경 사항 확인 방법 (git diff)
 
- **git diff**  
- 특징  
    - 작업 트리와 스테이지에 있는 파일의 차이  
    - 스테이지와 저장소에 있는 최신 커밋의 차이  
    - 특정 두 커밋 간의 차이  
    - 특정 두 브랜치 간의 차이  



<br><br>

## 🟢 1. 작업 트리(Working Directory) 관련 상세 비교

아직 커밋되지 않은 현재 작업 공간의 변경 사항을 추적하는 방법입니다.

### 🟡 파일 상태 및 통계만 확인하기
* `git diff --stat`
    * 변경된 파일 공간의 목록과 함께 어떤 파일에서 몇 줄이 추가(+)되고 삭제(-)되었는지 막대그래프로 시각화하여 요약해 줍니다.

### 🟡 특정 파일 또는 디렉토리만 지정해서 비교하기
* `git diff -- [파일명]`
    * 전체 변경 사항이 너무 많을 때, 특정 파일의 변경점만 골라서 집중적으로 확인할 수 있습니다.

* `git diff [디렉토리 경로]`
    * 특정 폴더 내부의 변경 사항만 제한하여 확인할 수도 있습니다.



### 🟡 의미 없는 공백이나 줄바꿈 무시하기

* `git diff -w` (또는 `--ignore-all-space`)
* 코드 자체는 바뀐 게 없는데 들여쓰기(Tab, Space)나 줄바꿈 문자 때문에 diff가 지저분하게 잡힐 때 사용합니다. 순수 코드 로직의 변화만 잡아내기 매우 유용합니다.






<br><br>

## 🟢 2. 스테이지(Staging Area) 및 커밋 관련 상세 비교

인덱스(Index)에 등록된 상태나 이미 기록된 커밋들을 비교하는 방법입니다.

### 🟡 스테이지에 올라간 파일들의 상세 변경점

* `git diff --staged`
* `git add` 명령어로 스테이징 영역에 올려둔 파일들이 직전 커밋(HEAD)과 비교해 어떻게 달라졌는지 보여줍니다. (`--cached`와 완전히 동일하게 동작합니다.)



### 🟡 작업 트리의 변경 사항과 스테이지를 모두 합쳐서 최신 커밋과 비교

* `git diff HEAD`
* `git add`를 한 파일과 안 한 파일 모두를 포함하여, 현재 내 PC에 있는 최종 결과물이 바로 직전 커밋(HEAD)과 비교해 무엇이 다른지 통틀어서 보여줍니다.






<br><br>

## 🟢 3. 커밋 간 및 특정 시점 상세 비교

과거 히스토리를 추적하고 버그가 발생한 시점을 찾아낼 때 유용한 비교 방법입니다.

### 🟡 두 커밋 간의 단순 파일 목록만 확인

* `git diff --name-only [커밋ID_A] [커밋ID_B]`
* 두 커밋 사이에 코드 내용이 아니라, 정확히 '어떤 파일들'이 수정되거나 추가되었는지 파일 이름만 리스트로 뽑아줍니다. 자동화 스크립트나 빌드 배포 대상을 추출할 때 자주 쓰입니다.



### 🟡 특정 날짜 및 시점 기준 비교

* `git diff master@{"1 week ago"}`
* 1주일 전의 master 브랜치 상태와 현재 master 브랜치 상태를 비교합니다.


* `git diff master@{"yesterday"}`
* 어제 시점의 코드와 비교하여 하루 동안 무엇이 바뀌었는지 추적합니다.






<br><br>

## 🟢 4. 브랜치(Branch) 간 상세 비교

협업 시 Pull Request(PR)를 보내거나 머지(Merge)하기 전에 충돌을 예방하기 위한 비교 방법입니다.

### 🟡 두 브랜치의 공통 조상부터 비교하기 (Three-Dot Refspec)

* `git diff [브랜치A]...[브랜치B]`
* 점 3개(`...`)를 사용하는 이 명령어는 실무에서 매우 중요합니다. 브랜치A와 브랜치B가 처음 갈라진 '공통의 조상 커밋'을 찾은 뒤, 그 조상으로부터 브랜치B까지 발생한 변경 사항만 보여줍니다.
* 브랜치A(예: main)에 그동안 다른 사람의 커밋이 쌓였더라도, 내가 브랜치B에서 작업한 순수한 변경 사항만 발라내어 볼 수 있습니다.



### 🟡 브랜치 간의 파일 상태 비교

* `git diff [브랜치A] [브랜치B] --name-status`
* 두 브랜치 간에 어떤 파일이 추가(A), 수정(M), 삭제(D)되었는지 상태 기호와 파일명만 깔끔하게 정렬해서 보여줍니다.






<br><br>

## 🟢 5. 고급 출력 제어 옵션

터미널에서 변경 사항을 더 직관적으로 읽기 위한 추가 옵션들입니다.

### 🟡 단어 단위로 변경 사항 확인

* `git diff --word-diff`
* 기본 diff는 줄(Line) 단위로 수정 여부를 판단하지만, 이 옵션을 쓰면 한 줄 안에서 정확히 어떤 '단어'가 바뀌었는지 `[-삭제된단어-]`와 `{[+추가된단어+]}` 형태로 짚어줍니다.



### 🟡 소스코드 내 함수 이름 표시

* `git diff -p`
* 변경된 코드 조각(Hunk)이 어떤 함수나 클래스 내부에서 일어난 일인지 상단에 함수명을 함께 표시해 주어 코드의 문맥을 파악하기 쉽게 도와줍니다.






<br><br>

## 🟢 종합 명령어 확장 표

| 비교 시나리오 | 최적의 명령어 조합 | 비고 |
| --- | --- | --- |
| 공백 변경은 무시하고 코드 로직만 비교 | `git diff -w` | 스타일 수정 제외할 때 유용 |
| 스테이지에 올린 파일의 이름과 상태만 확인 | `git diff --staged --name-status` | 커밋 전 최종 목록 점검 |
| 3일 전 커밋 상태와 현재 상태 비교 | `git diff HEAD@{"3 days ago"} HEAD` | 최근 작업 추적 |
| main 브랜치에서 갈라져 나온 이후 내 브랜치의 변경점만 보기 | `git diff main...my-feature` | 점 3개(`...`) 사용에 주의 |
| 두 커밋 간 변경된 파일들의 요약 통계 | `git diff --stat [커밋A] [커밋B]` | 대규모 변경 확인용 |
