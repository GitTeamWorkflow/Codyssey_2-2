# 🟩 GitHub Flow 개요  

## 🟢 GitHub Flow란 무엇인가?  
GitHub Flow는 협업을 할 때 코드를 안전하고 끊김 없이 공유하고 합치기 위한 단순한 작업 흐름이다.  
여러 사람이 하나의 프로그램을 만들 때 서로의 코드를 덮어쓰지 않고 안전하게 합치기 위해 사용한다.  

<br><br>

## 🟢 GitHub Flow의 5단계 흐름  
기본적으로 아래의 흐름을 반복하며 프로젝트를 진행한다.  

<br><br>

### 🟡 1단계: 브랜치 만들기 (Create a Branch)  
- 새로운 기능 추가나 버그 수정을 시작할 때 기존의 안전한 코드(main 브랜치)에서 복사본을 만든다.  
- 이 복사본을 브랜치(Branch)라고 부른다.  

<br><br>

### 🟡 2단계: 코드 변경하고 저장하기 (Add Commits)  
- 만든 브랜치에서 코드를 수정하거나 새로운 기능을 만든다.  
- 변경된 내용을 저장하는 것을 커밋(Commit)이라고 한다.  

<br><br>

### 🟡 3단계: 풀 리퀘스트 보내기 (Open a Pull Request)  
- 작업이 끝나면 "내가 만든 코드를 원래 코드에 합쳐주세요!"라고 요청을 보낸다.  
- 이 요청을 풀 리퀘스트(Pull Request, 줄여서 PR)라고 부른다.  

<br><br>

### 🟡 4단계: 코드 검토하고 토론하기 (Discuss and Review)  
- 동료들이 내가 보낸 코드를 읽고 의견을 나눈다.  
- 문제가 없거나 개선할 점을 수정한 뒤 승인을 받는다.  

<br><br>

### 🟡 5단계: 코드 합치기 (Merge and Deploy)  
- 검토가 끝난 코드를 원래 코드(main 브랜치)에 합친다.  
- 코드를 합치는 행동을 머지(Merge)라고 한다.  

<br><br>

## 🟢 전체 흐름 요약표  
| 단계 | 작업 내용 | 사용하는 주요 개념 |  
| :--- | :--- | :--- |  
| 1 | 브랜치 생성 | Branch (나뭇가지, 가지치기) |  
| 2 | 코드 수정 및 저장 | Commit (제출, 약속) |  
| 3 | 합치기 요청 | Pull Request (당겨서 합쳐달라는 요청) |  
| 4 | 코드 검토 | Review (다시 보기, 검토) |  
| 5 | 코드 병합 | Merge (융합, 합치기) |
