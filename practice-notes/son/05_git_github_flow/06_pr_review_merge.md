# 🟩 코드 리뷰 및 병합  
## 🟢 코드 리뷰와 병합이란 무엇인가?  
코드 리뷰(Code Review)는 동료들이 내가 보낸 코드 변경 사항을 검사하고 조언을 해주는 과정이다.  
병합(Merge)은 검토가 완료되어 승인된 코드를 최종적으로 main 브랜치에 합치는 기능이다.  

<br><br>

### 🟡 영어 단어 및 용어 풀네임  
| 용어 | 풀네임 (Full Name) | 해설 |  
| :--- | :--- | :--- |  
| Code Review | Code Review (코드 검토) | 작성한 코드를 동료들과 함께 읽으며 실수를 찾아내고 성능을 개선하는 협업 방식이다. |  
| Merge | Merge (병합하다, 합치다) | 쪼개져 있던 브랜치의 코드 변경 내용을 하나의 브랜치로 모아서 합치는 기능이다. |  
| Pull | Pull (당기다, 가져오다) | 원격 저장소에 저장되어 있는 최신 코드 데이터를 나의 로컬 컴퓨터로 다운로드하여 합치는 행위이다. |  

<br><br>

## 🟢 실습하기: 리뷰 후 코드 합치기 및 내 컴퓨터 동기화  

<br><br>

### 🟡 1. 피드백 반영 및 승인받기  
GitHub PR 페이지 내 `Files changed` 탭에서 동료들이 남겨준 코멘트를 확인한다.  
의견을 수렴해 코드를 수정한 뒤 다시 `git push`를 보낸다. 최종 승인(Approve)을 얻을 때까지 이 과정을 반복한다.  

<br><br>

### 🟡 2. Merge pull request 버튼 클릭  
최종 승인이 완료되면 PR 페이지 하단에 초록색 `Merge pull request` 버튼이 활성화된다.  
이 버튼을 누르고 `Confirm merge`를 클릭하면 내가 작업했던 브랜치의 코드들이 main 브랜치로 합쳐진다.  

<br><br>

### 🟡 3. 로컬 컴퓨터를 최신 코드로 동기화하기  
인터넷 상(GitHub)에서는 코드가 성공적으로 합쳐졌지만, 내 컴퓨터(로컬)의 main 브랜치는 아직 예전 상태 그대로이다.  
내 컴퓨터도 최신 상태로 만들어 주어야 한다.  

<br><br>

#### ⚫️ 3-1. 로컬의 main 브랜치로 이동하기  
```bash
git checkout main
```
또는 최신 명령어로 스위치한다.  
```bash
git switch main
```

<br><br>

##### ⚙️ 명령어 해설  
| 명령어 | 의미 | 해설 |  
| :--- | :--- | :--- |  
| git checkout main | checkout main | 내 작업 공간을 로컬 컴퓨터의 main 브랜치로 이동시킨다. |  
| git switch main | switch main | 내 작업 공간을 로컬 컴퓨터의 main 브랜치로 안전하게 전환한다. |  

<br><br>

#### ⚫️ 3-2. 최신 코드 가져오기  
```bash
git pull origin main
```

<br><br>

##### ⚙️ 명령어 해설  
| 명령어 | 구성 요소 풀네임 | 해설 |  
| :--- | :--- | :--- |  
| git pull | pull (당겨오다) | 원격 저장소에 새로 합쳐진 최신 버전을 내 로컬 컴퓨터 브랜치로 내려받아서 병합(Merge)해 준다. |  
| origin | origin (근원, 원격 저장소 별칭) | 연결된 인터넷 저장소(GitHub 주소)에서 가져오겠다는 뜻이다. |  
| main | main (기본 브랜치) | 원격 저장소의 main 브랜치에 해당하는 최신 이력을 가리킨다. |
