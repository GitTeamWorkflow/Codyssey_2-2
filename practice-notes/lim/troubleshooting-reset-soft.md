# 트러블슈팅 상세 — 로컬 커밋 취소 후 변경 유지 (`git reset --soft HEAD~1`)

> **참여자:** Lim
> 팀 `troubleshooting-log.md` 의 #2 항목을 개인 학습용으로 풀어 쓴 상세 노트.
> 한 줄 요약: **push 전 로컬 커밋만 되돌리고, 작업 내용은 staging에 그대로 살려** 더 적절한 단위/메시지로 다시 커밋했다.

---

## 1. 상황 (What happened)

문서 수정 중 **아직 분리해야 할 변경사항을 한 커밋에 함께 담아버렸다.** 원격에 push하기 전이었으므로, 커밋 자체는 취소하되 작업한 내용은 잃지 않고 staging 상태로 유지한 뒤 다시 정리해 커밋했다.

---

## 2. 먼저 알아야 할 것 — `reset` 이 건드리는 3개의 영역

`git reset` 은 "어느 단계까지 되돌릴지"를 옵션으로 고른다. Git의 3영역을 기억하면 옵션 차이가 한눈에 들어온다.

```text
worktree(작업파일)  ──add──▶  staging(index)  ──commit──▶  repo(커밋history)
```

| 옵션 | 커밋 취소 | staging 유지 | worktree 유지 | 한 줄 의미 |
| --- | :--: | :--: | :--: | --- |
| `--soft` | ✅ | ✅ | ✅ | 커밋만 풂. 변경은 **staging에 그대로** |
| `--mixed` (기본) | ✅ | ❌ | ✅ | 커밋+add 풂. 변경은 worktree에 |
| `--hard` | ✅ | ❌ | ❌ | **변경까지 삭제** (위험) |

> 이번 상황은 "**커밋 메시지/단위만 다시 짜고 싶다**" 였으므로, 변경을 그대로 들고 있는 `--soft` 가 정답.

---

## 3. 사용한 명령어 (+ 각 명령이 한 일)

```bash
git log --oneline -3          # ① 최근 커밋 3개 확인 — 되돌릴 대상이 로컬 커밋인지 점검
git reset --soft HEAD~1       # ② 마지막 커밋을 풂. 변경은 staging에 유지
git status                    # ③ "Changes to be committed" 에 파일이 살아있는지 확인
git commit -m "docs: add lim practice note"   # ④ 적절한 단위/메시지로 다시 커밋
```

- `HEAD~1` = "현재 커밋의 한 칸 전" → 즉 **마지막 커밋 1개**를 되돌린다.
- `--soft` 라서 ②에서 파일이 사라지지 않고 ③에서 staged 상태로 그대로 보인다.

---

## 4. 해결 절차

1. `git log --oneline -3` 으로 최근 커밋을 확인했다.
2. 되돌릴 커밋이 **로컬 커밋인지(아직 push 전인지)** 확인했다.
3. `git reset --soft HEAD~1` 로 최근 커밋을 취소했다.
4. `git status` 로 변경사항이 staging 상태에 남아 있는지 확인했다.
5. 변경 파일을 작업 단위에 맞게 확인한 뒤 다시 커밋했다.

---

## 5. 결과 (Outcome)

작업 내용은 **하나도 잃지 않고** 커밋만 취소하여, 더 적절한 커밋 메시지와 작업 단위로 정리했다.

---

## 6. 주의점 & 트레이드오프

- `--soft` 는 변경을 **staging** 에, `--mixed`(기본)는 **worktree** 에 남기고, `--hard` 는 **삭제**한다 → 옵션 선택이 곧 위험도.
- `reset` 은 **히스토리(커밋 포인터)를 바꾼다.** 그래서 **push 전 / 혼자 작업한 커밋** 에만 안전하다.
- 이미 push해 **공유된 커밋**이라면 `reset` 대신 **`revert`** (되돌리는 새 커밋 추가, 기록 보존)를 써야 한다 — 공유 히스토리 재작성은 팀 작업을 깨뜨린다(미션 제약).
- 단순히 **직전 커밋 메시지만** 고칠 거라면 `git commit --amend` 가 더 간단하다.

### 언제 무엇을? (한눈 비교)

| 하고 싶은 것 | 쓰는 것 |
| --- | --- |
| 직전 커밋 메시지/내용만 손보기 | `git commit --amend` |
| 로컬 커밋 취소 + 변경 유지해 다시 커밋 | `git reset --soft HEAD~1` |
| 이미 push된 커밋을 안전하게 취소 | `git revert <hash>` |
